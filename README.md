# python_qa_vera

# Автоматизация тестирования на Python с использованием Pytest и Allure

Этот проект содержит автоматизированные E2E-тесты для веб-калькулятора со встроенной задержкой и интернет-магазина "Sauce Demo". Тесты написаны на **Python** с использованием фреймворка **Pytest**, шаблона проектирования **Page Object Model (POM)** и инструмента для генерации отчетов **Allure**. Взаимодействие с браузерами реализовано через **Selenium WebDriver**.

---

##  Структура проекта и исходные файлы

Проект разделен на логические слои (тесты и страницы):

*   `test_calc.py` — тесты для проверки функциональности веб-калькулятора в браузере Google Chrome.
*   `test_shop.py` — тесты для проверки сквозного сценария покупки в интернет-магазине в браузере Mozilla Firefox.
*   `pages/` — директория, содержащая классы страниц (Page Objects) для изоляции локаторов и логики взаимодействия с UI:
    *   `CalcPage` — страница калькулятора (настройка задержки, ввод данных, чтение дисплея).
    *   `ShopPage` — базовый класс для страниц магазина с инициализацией драйвера и явных ожиданий.
    *   `StandardPage` — страница авторизации (ввод учетных данных).
    *   `InventoryPage` — каталог товаров (добавление позиций в корзину, переход к корзине).
    *   `CartPage` — страница корзины (проверка содержимого, переход к оформлению).
    *   `CheckoutPage` — страница оформления заказа (заполнение персональных данных, проверка финальной стоимости).

##  Стандарты разработки и документирования кодовой базы

В проекте строго соблюдаются требования к чистоте, типизации и документированию кода:

### 1. Строгая аннотация типов (Type Hinting)
Все методы классов страниц содержат явное указание типов входных параметров и типов возвращаемых значений (включая составные типы, такие как `list[str]`, `tuple[str, str]` и объекты Selenium `WebDriver`).

### 2. Подробные Docstrings
Каждый публичный метод снабжен документированием в стиле Google/Sphinx. В комментариях отражены:
* Краткое описание выполняемого бизнес-действия на странице.
* Блок `Args:` с подробным перечислением параметров и их ожидаемых типов.
* Блок `Returns:` с описанием типа возвращаемого значения (или `None`).

*Пример оформления метода из проекта:*
```python
def fill_checkout_form(self, first_name: str, last_name: str, zip_code: str | int) -> None:
    """
    Заполняет форму оформления заказа персональными данными покупателя.

    Args:
        first_name (str): Имя покупателя.
        last_name (str): Фамилия покупателя.
        zip_code (str | int): Почтовый индекс (принимает строку или число).
    """
```

### 3. Интеграция с Allure Report в коде
В слое тестов реализована полная разметка для построения детализированных отчетов:
* Использованы декораторы `@allure.epic`, `@allure.feature` и `@allure.story` для структурирования тест-сьютов.
* Шаги внутри тестов обернуты в контекстный менеджер `with allure.step(...)` для логирования действий.
* Проверки состояния (assertions) снабжены понятными текстовыми описаниями внутри шагов Allure.

##  Предварительные требования

Перед запуском проекта убедитесь, что в вашей системе установлены:
1. **Python** (версии 3.10 или выше).
2. Браузеры **Google Chrome** и **Mozilla Firefox**, а также совместимые с ними версии драйверов (`chromedriver`, `geckodriver`).
3. **Allure CLI** (системная утилита командной строки для генерации HTML-отчетов).

##  Инструкция по запуску тестов и сборке отчетов

### Шаг 1. Установка пакета allure-pytest
Пакет необходим для интеграции фреймворка Pytest с репортером Allure.

1. Откройте терминал и перейдите в вашу рабочую директорию:
   ```bash
   cd "lesson_10"
   ```
2. Установите необходимый плагин:
   ```bash
   pip install allure-pytest
   ```

### Шаг 2. Запуск тестов и сбор результатов
Запустите прогон тестов с автоматической генерацией сырых логов Allure в специальную папку:
```bash
python -m pytest --alluredir allure-result
```
> **Результат:** После завершения тестов в корне проекта создается директория `allure-result`, содержащая JSON-файлы с результатами проверок и шагов.

### Шаг 3. Установка утилиты Allure Report (если не установлена)
Для того чтобы операционная система могла обработать результаты и собрать красивый интерфейс, требуется консольный инструмент Allure.

**Для пользователей Windows (через менеджер пакетов Scoop):**
```bash
# Разрешение на запуск скриптов в PowerShell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
# Установка Scoop
Invoke-RestMethod -Uri https://scoop.sh | Invoke-Expression
# Установка Allure CLI
scoop install allure
```

### Шаг 4. Генерация и просмотр интерактивного отчета
Чтобы скомпилировать файлы из `allure-result` в веб-интерфейс и автоматически открыть его в браузере по умолчанию, выполните:

```bash
allure serve allure-result
```
> **Инфо:** Команда поднимет локальный веб-сервер. Чтобы закрыть его и завершить просмотр отчета, нажмите `Ctrl + C` в окне терминала.
